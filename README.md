## What is 0G Agent Swarm OS?

0G Agent Swarm OS is the **intelligence layer** for decentralized AI agent collaboration. While 0G provides the infrastructure (storage, compute, data availability, and blockchain), this app builds on top of it to enable multiple AI agents to work together on complex tasks through a shared memory system.

### How It Works

1. **User submits a task** via the dashboard
2. **Planner Agent** breaks the task into execution steps and writes the plan to 0G Storage Simulation
3. **Researcher Agent** fetches the plan from 0G Storage Simulation, gathers research data, and stores findings
4. **Executor Agent** fetches stored research data from 0G Storage Simulation and generates the final output
5. **Critic Agent** reviews the output for quality and accuracy, stores feedback with a score

All agent interactions are stored in **Shared Memory (0G Storage Simulation)**, creating a transparent, persistent record of the entire collaboration process. Each agent reads from and writes to the same shared memory, demonstrating the decentralized collaboration pattern.

## How It Uses 0G

> **Current Status:** This hackathon demo uses **simulated 0G Storage** (in-memory store) with clear integration points. The architecture is designed to plug directly into the real 0G Storage SDK — all data flows, entry types, and API patterns map 1:1 to 0G's content-addressable blob storage.

| 0G Component | Role in Agent Swarm OS | Current Implementation |
|---|---|---|
| **0G Storage** | Persistent, decentralized memory for all agents. Task data, plans, research, outputs, and feedback are stored as content-addressable blobs. | Simulated via in-memory store with `storageStatus` tracking |
| **0G Compute** | Decentralized AI inference powering each agent's intelligence. | Currently uses Groq LLM API (with mock fallback) |
| **0G DA Layer** | Scalable data availability for agent communication logs and workflow events. | Simulated via in-memory log store |
| **0G Chain** | Verifiable task ownership and execution records on-chain. | Simulated via log entries with TODO markers |

### What Data Would Be Stored on 0G

In a production deployment, the following data flows through 0G Storage:

- **Task Data** — User-submitted task descriptions and metadata
- **Planner Output** — Structured execution plans generated by the Planner Agent
- **Research Data** — Research findings and source data from the Researcher Agent
- **Executor Output** — Final deliverable/report from the Executor Agent
- **Critic Feedback** — Quality review scores and improvement notes from the Critic Agent
- **Final Result** — Combined output with review score and approval status

## AI Integration (Groq API)

Agent responses are powered by **Groq's fast LLM inference** using the `llama-3.3-70b-versatile` model. Each agent has a distinct system prompt:

| Agent | System Prompt Role |
|---|---|
| **Planner** | Breaks user tasks into 4-6 clear, actionable steps |
| **Researcher** | Generates structured research notes and findings based on the plan |
| **Executor** | Creates the final deliverable report using task, plan, and research data |
| **Critic** | Reviews the output for quality, provides a score out of 100 with improvement notes |

### Fallback Mode

If no `GROQ_API_KEY` is provided, the app automatically falls back to **mock responses** so the demo still works without any API key. The UI shows whether responses were powered by "Groq LLM" or "Mock Responses".

## Setup Instructions

### Prerequisites

- Node.js 18+ installed
- npm 8+
- (Optional) Groq API key for real AI responses

### Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/RukonKholifa/0G-Agent-Swarm-OS.git
cd 0G-Agent-Swarm-OS

# 2. Install all dependencies
npm run install:all

# 3. (Optional) Add your Groq API key
cp .env.example .env
# Edit .env and add your GROQ_API_KEY
# Get a free key at: https://console.groq.com/keys

# 4. Start the development servers (frontend + backend)
npm run dev
```

The app will be available at:
- **Frontend:** http://localhost:5173
- **Backend API:** http://localhost:3001

### Adding Groq API Key

1. Get a free API key from [Groq Console](https://console.groq.com/keys)
2. Create a `.env` file in the project root:
   ```
   GROQ_API_KEY=your_groq_api_key_here
   ```
3. Restart the backend server
4. The server will log `Groq LLM enabled` on startup

Without the key, the app uses mock responses — the demo is fully functional either way.

### Production Build

```bash
# Build the frontend
npm run build

# Start the server (serves the built frontend)
cd server && npm start
```

The production app will be available at http://localhost:3001.

## Demo Flow

1. **Open the dashboard** at http://localhost:5173
2. **Enter a task** in the "Create New Task" input (e.g., "Research & create a market analysis report on AI agents")
3. **Click "Run Task"** to start the agent swarm
4. **Watch the workflow** as each agent activates in sequence:
   - Planner breaks the task into steps (writes plan to 0G Storage Simulation)
   - Researcher fetches the plan, generates research findings (stores in 0G Storage Simulation)
   - Executor fetches research data, creates the final report (stores in 0G Storage Simulation)
   - Critic reviews the output, provides a quality score (stores feedback in 0G Storage Simulation)
5. **Monitor Shared Memory** panel — see each entry appear with "Stored in 0G Storage Simulation" status
6. **Check Live Logs** — see "Planner wrote plan to 0G Storage Simulation", "Researcher fetched planner output from 0G Storage Simulation", etc.
7. **View Final Output** — completed report with review score and LLM source badge

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/tasks` | Create and run a new task |
| `GET` | `/api/tasks` | List all tasks |
| `GET` | `/api/tasks/:id` | Get task details with agent status |
| `GET` | `/api/tasks/config/status` | Check if Groq LLM is configured |
| `GET` | `/api/memory` | Get shared memory entries (0G Storage Simulation) |
| `GET` | `/api/memory/stats` | Get system statistics |
| `GET` | `/api/memory/logs` | Get live activity logs |
| `DELETE` | `/api/memory` | Clear all memory (reset simulation) |
